1.0.5.2 2026-09-29 · 安全加固版：GC 修复 + Smokeroor + 编译缓存
  • 修复 @5/@6 一跑就崩（访问违例 0xC0000005）：GC 的 sweep 自己就逐个回收垃圾，却又递归释放子对象 —— 子对象若排在父前面已被 free 过，父再释放就踩悬空指针。原来 @normal 141ms 跑完的负载，@5/@6 必崩；现在正常
  • 修复 @6 慢 100 倍：minor GC 会顺着老年代往下摸整个可达图，退化成半个全堆标记；而且 major GC 从不自动跑（增量是死代码）。加了代际隔离 + 老年代超 2MB 自动点火增量标记，9860ms → 234ms（提速 42 倍），@6 相对 @normal 的开销从 70 倍降到 1.66 倍
  • 补上增量标记的写屏障（黑分配 + 删除屏障 + 插入屏障）：以前增量标记期间改指针会漏标、被当垃圾收走。实测 60000 对象 + 400 轮高频改引用，校验 0 错
  • 新增 Smokeroor 安全体检：python smokeroor.py 一条命令出红绿灯报告。配 smoke.* 14 个检查函数（零成本），smoke.check(v) 一行看懂变量是 [OK] / [DELETED] / [DANGLING]
  • 期望驱动 + 错误指纹库：新错误来了只加声明不改源码（--learn 自动生成期望）；见过的错秒认（标 [已知]）。不符自动重试，还不符就红 + 明确 diff + 基线揪出新增失败
  • 编译提速 6.5 倍：源码 / 引用库 / 编译器 / 运行时都没变就直接跑上次的 exe（冷 9.95 秒 → 热 1.52 秒）。改源码或改运行时自动失效
  • 修复 @self 悬垂指针：手动删除后共享别名访问原来是「后果自负」（野指针），现在报 用已删除变量 干净退出 —— 这是唯一能让 PYbook 段错误的地方
  • 新增 te.chr(码点)：PYbook 字符串不支持转义，这是产生换行 / 回车的唯一出口（te.chr(10) 换行、te.chr(13) 回车）。顺带解锁了 HTTP（CRLF 能发了）
